# Wreckabulary lobby: room first, clear choices

STATUS: DESIGN REVIEW COMPLETE; implementation and native acceptance are tracked by the root lane. Research checked 26 October 2026. This is an original direction using Wreckabulary's existing artwork, not a request to copy another game's interface or assets.

Keep the vivid sunroom, large original character, warm cream surfaces and dark readable lettering. The main improvement is to explain where each action goes with a few familiar labels. Preserve a quick local start; give actual online play its own explicit entrance. Avoid turning the beautiful room into a dashboard.

## Official references and the limited lesson taken

| Primary reference | What the source supports | Wreckabulary decision / inference |
| --- | --- | --- |
| [Xbox XAG 112 — UI navigation](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112) | Consistent locations/actions, logical focus order, digital keyboard/controller navigation and a reliable return path. Linear looping guidance is distinct from a multi-directional grid. | Keep Select/Back in stable positions. A row or grid must move focus in its visual direction, restore focus on return, and keep selected content visible. This is a design target, not an accessibility certification. |
| [Xbox XAG 113 — UI focus](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/113) | A clear visible focus indicator, including when dialogs open; focus must not disappear onto hidden controls. | Use a dark outline plus warm highlight, not colour alone or a tiny underline. A modal owns focus until closed. Preserve an obvious selected state separately from focus. |
| [Xbox XAG 101 — text](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101) | Readability is based on rendered glyph body height, not a nominal font-size property; PC default guidance is 18 px at 1080p, with scalable text and no loss of content. | Remove unnecessary words before shrinking text. Use original display type for short headings, body type for descriptions; measure actual captures. Larger UI/text requires vertical scrolling, not clipped buttons or horizontal reading. |
| [Xbox XAG 102 — contrast](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102) | Important standard text/visual cues use 4.5:1 contrast, large elements 3:1; colour alone is insufficient. Contrast over art uses the least favourable background area. | Keep small labels on solid cream. Check focus/disabled text per theme. Do not wash out selectable equipment/skin art to indicate ownership. Use lock/check/price plus a readable action state. These ratios remain a measurement gate. |
| [Xbox XAG 117 — motion](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/117) | Players benefit from controls to stop distracting menu movement and adjust secondary camera motion. | Existing Reduce theme motion belongs in a discoverable Accessibility group. Any future card wiggle, camera drift and ambient loop must honour the intended setting or receive its own clearly scoped control. Current toggle coverage must be tested rather than assumed. |
| [Epic Parties FAQ](https://www.epicgames.com/help/c-36624475/c-Trending_0/epic-a22007555) | Epic distinguishes party joinability from participation; its current Joinable/Invite Only setting applies to the current party and is visible in party controls. | Distinguish a Wreckabulary party from a match queue, and local devices from remote humans. Show public/private status where it actually applies. Epic's friends, account preferences, voice and cross-product behaviour are references only; do not imply Wreckabulary implements them. |
| [Rocket League — private matches](https://www.epicgames.com/help/c-37599050/a24641297) | Its Play menu separates creating and joining a private match; joining uses explicit credentials and a matching region. | Wreckabulary's actual code-based private route should have separate Create/Join actions and persistent region feedback. Do not adopt Rocket League's name/password protocol. |
| [Rocket League — local split-screen on PC](https://www.epicgames.com/help/c-37599050/c-42869540/a14250290) | Its local join flow starts from a second controller in the main menu. | Show a concise controller join cue beside Local party. Wreckabulary also supports its own right-keyboard input, so use current binding glyphs rather than copying Rocket League's controller requirements. |

## Navigation and truthful capabilities

The top row should expose **Customize · Play · Shop · Career**. Leaderboards belong under Career after route tests; until that move is implemented, retaining the existing separate entry is safer than hiding a working destination. Settings remains a consistent gear with a text tooltip/focus label. Keep internal `LOADOUT`/page identities stable when the visible name becomes Customize.

Home's dock becomes **LOCAL PLAY**, selected mode, selected house, **ONLINE PLAY**, and the short note **Human players · Public / private**. Local Play retains `Menu.Go`, selected state and its cancellable countdown. Online Play retains `Menu.OpenWordbound`; it does not silently convert the selected house mode to an online match. Top Play opens the full chooser, where selected participant details appear. No Home seat-summary tooltip was implemented. The approved Home migration changes only these three exact saved strings.

Play has three destinations: **Local / Online / Create**. Local chooses the original house modes. Online opens the working Wordbound launcher directly. Create contains **Learn** and the current home-decoration workshop; Wordbound map editing stays explicitly separate in its own launcher. Do not present the blocked legacy Matchmaking cards as working online modes.

Solo, Bots and Couch describe the selected local experience; they are not three mutually exclusive global modes. Dibs with one human is a solo participant plus three bots. Dibs with couch players can still include bots. Double trouble assigns the first two humans to opposite teams, each with a bot; do not promise a human duo against bots. Moving Out, Moving Day and Escape use humans without AI crew. The tutorial observes joined local players, so it must not be labelled solo-only. Use the [source capability matrix](../modes/capability-matrix.md) for exact capacities, online formats and route limits.

Online's **Solo / Duo / Squad** means team size in the existing race formats. It is not an offline/online switch. **Fill** recruits humans; never depict it as bots. Public/Private is match access; Party is the invited group; Local 1/4 is devices on this PC. No current couch-to-online multi-identity support should be implied. A public co-op queue with one human needs Fill or another human. These are source-derived restrictions, not new policy proposed by the art lane.

## Visual composition and concise copy

Retain the present Home camera initially (saved distance 4.2, eye height .95, look height .5, FOV 30). The character already owns the central empty floor and sky opening. Do not regenerate the sunroom or add more decorative panels before route clarity is fixed. Keep top navigation compact, room visible, and the lower-right launch dock outside the character silhouette. At small sizes, reduce simultaneous cards and scroll rather than shrinking all controls with the existing fit transform.

Local mode cards should show original art, existing title and one short category tag. Show the selected objective and real participant summary once in the footer. Example: Dibs! → “Smash. Spell. Last one standing.” plus “You + 3 bots”. A map card needs its name and useful room/floor facts; decorative prose is optional detail. Keep category words and focus readable without understanding the artwork.

Use one cream surface per panel, a single border treatment and consistent spacing. Original colour stays in avatars, items, swatches and themes. Teal indicates current navigation/action emphasis; warm gold and a check identify selection. Do not make every card glow, rotate or pulse. Pointer hover and keyboard focus should reveal the same useful detail. Keep locked or unaffordable art full colour; availability lives in the action and lock/price marker.

The two current escape names are confusing: The great escape is keepsakes-to-van; The Escape! is word locks. Near-term retain saved mode IDs and show distinct objective/art tags. A later owner-approved naming pass could use “Moving out” and “Word escape”; this report does not rename existing mode identifiers.

## Customize, Shop, settings and controls

Customize keeps the full 3D hero left and a right-side editor. Immediate changes: use short Done text, maintain current preview/equip restoration, move dense explanatory copy to selected detail, keep swatches large enough to select. A later saved-layout slice can separate **Outfit / Gear / Recipes**: outfit and accessories change the avatar, Gear sets cosmetic finishes, Recipes explains gameplay. Do not add those tabs until typed bindings, authoring and navigation tests exist. Whole-gear finish changes remain clearly labelled Apply to all; per-recipe overrides remain visible.

Shop keeps its current six alpha portraits and mint cards. Selection previews the real character; Equip or a visible price is a separate action. Keep purchase, preview and equipped states distinct. Rooms means lobby themes, not playable maps; label that category **Lobby rooms** if tests show ambiguity. Extras are appearance/emotes. Do not introduce paid power claims: current How to play correctly says cosmetics do not change stats. No new currencies, checkout or online economy are proposed.

The frozen Settings slice groups existing controls into **Profile / Audio / Gameplay / Graphics / Controls / Help**. Profile contains name and the appearance entry; Gameplay contains current combat feedback and Reduce theme motion. This preserves working controls without implying a complete accessibility settings suite. A later Accessibility grouping is a discoverability proposal, not implemented scope. Display changes retain the timed Keep/Revert safety flow and must not overlap a scrolled panel. Controls keeps actual keyboard remapping, sensitivity and invert-Y. Controller bindings are currently fixed: display that fact briefly instead of implying remapping support. A later concise-controls pass can show one selected binding explanation; the existing clear listening state and visible Cancel must remain. Help retains original-item illustrations and current binding explanations; this slice does not replace its artwork.

## Acceptance before calling the redesign ready

1. New player can identify Local, Online, Customize and Shop from the first screen without a tooltip. Existing user can still quick-start the selected local mode.
2. Keyboard and controller can open each destination, select an item, scroll to its focused row, cancel a remap, close a modal and return to the original control. No invisible/offscreen focus.
3. Home/Local/Create/Settings/Shop/Customize captures at 1280×720 and 1920×1080 show no clipped labels, overlap or character obstruction. Test the existing minimum supported size separately; do not infer it from a larger render.
4. Rendered text body height/contrast is measured; expanded UI/text remains usable. Fewer words must not hide capacity, bot, price, ownership or public/private information.
5. Save a real prefab layout edit, reopen, launch the matching Workspace preview and verify it survives. Run migration twice and prove no second save. Preserve source and asset metadata receipts.
6. Local human/bot configurations and online public/private flows are verified against the capability matrix. A lobby screenshot is not proof that every original mode has been networked.

No new artwork is needed to make this slice better. The highest-value work is clear route names, truthful party summaries, visible Shop access and stable input/focus, followed by native visual checks. James's final visual/play acceptance remains pending.
