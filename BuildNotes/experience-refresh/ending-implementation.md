## Implemented contract

`WordboundStoryPlan.Epilogue(MatchSnapshot frame, string actor, ModeDefinition mode)` returns null or immutable `WordboundStoryEpilogue` with `Id`, `Title`, `Cue`, `ResultKey`. Existing constructors and notice identities are unchanged. Copy is resolved with the existing optional profile/localizer at plan construction, matching existing clue behavior.

Six IDs only: `TimeRunSuccess`, `TimeRunExpired`, `RaceDelivery`, `RaceProgressWin`, `RaceProgressDraw`, `RaceDefeat`. Canonical TimeRun success remains `Win`; the first ID is presentation copy only. Final delivery takes priority on the exact time-limit tick. Mandatory Repair is part of the existing flagship route; there is no optional Restoration branch or completion claim.

The resolver requires a confirmed, non-migrating snapshot; exact course source/manifest and mode binding; matching local roster seat/team; a connected, non-returned reader; and consistent winners/outcome/tick. It checks canonical finishers or elapsed-limit progress winners before choosing copy. Homecoming additionally requires the own-team earned `3:L3_Rooftop_GardenGate` journal entry. Unknown/custom course documents (even with the flagship ID), different geometry catalogues, wrong actor, contradictory results and unsupported modes return null. FreeForAll/Freestyle never get these endings.

The resolver assumes the gameplay layer supplied an already validated snapshot; it is not another wire validator. It performs no mutation or caching. Result identity is binding hash, own team, result tick, canonical outcome and sorted winners, formatted invariantly; it excludes epoch, sequence and wall clock. A provisional snapshot stays hidden even after a later confirmed snapshot at the same tick is processed. New transport/readiness state must be gated by the caller because it is not encoded in this API's snapshot.

`WordboundStoryProfile.Epilogues` contains `WordboundStoryEpilogueCopy { Id, Title, Cue }`; title fallback max 48 characters and cue max 96. Validation rejects unknown/duplicate IDs, invalid text/key data and more than six rows. Null/empty legacy lists and missing entries use built-in key/fallback copy without changing the asset. `AddMissingEpilogues()` adds only absent defaults, returns the number added and preserves existing rows, titles, clues and chapter copy. The Inspector offers this operation with Undo and a copy preview. New empty-profile population includes endings; old profiles do not need regeneration.

Editing: select the installed StoryProfile asset, use **Add missing epilogue copy** if desired, then edit only Title/Cue keys and fallback copy under an existing ID. The preview does not grant progress. Keep fallback text concise; localization is a key/fallback seam, not a shipped translation service. Recreate/rebind the presentation plan to apply runtime copy changes.
