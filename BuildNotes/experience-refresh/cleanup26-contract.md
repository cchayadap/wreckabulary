## Recommended phase-barrier contract

Preserve the old cross-party ordering, with two explicit phases:

1. Snapshot the fixture-owned Clients and PartyGroups once after native/session shutdown and pending gameplay tasks have settled. Validate at most8 unique clients, at most8 groups, unique group IDs and no client assigned to two groups. Use only the original clients and recorded memberships; never discover unrelated parties or invent credentials.
2. **Return barrier:** when Expected is present, start one return attempt per authenticated original client, with concurrency capped at8 (the fixture's admitted maximum). Await every result, including failures, before any Cancel/Leave chain begins. Each attempt returns a receipt instead of faulting/cancelling sibling work. No Task.Run around Unity work is necessary; these are asynchronous HTTP operations. A failure is retained even if later cancellation/leave succeeds.
3. **Party chains:** run independent recorded parties concurrently, bounded by the same8-client maximum. Within a party: original leader GET Party -> one Cancel -> reverse member order, each with Profile -> verify exact recorded party -> GET latest Party revision -> one Leave -> Profile confirming no partyId. Keep the original leader until last. Never run two leave mutations for the same party concurrently. No global barrier is needed between independent parties' cancel/leave work once all returns have settled.
4. An earlier return or cancel failure does not suppress the next cleanup stage. The service may have applied a write before its response was lost, so allow the later stage to run with its own fresh read/budget; server guards decide whether it is legal. Preserve the earlier failure regardless. If a required read fails or membership changes, record the stage as failed/blocked and do not fabricate a revision or target another party. “Attempt every stage” does not mean issuing an unsafe mutation without its prerequisite data.
5. Keep the existing no-membership check as a verified already-left outcome. For new successful return receipts, validate returned state/actor against the original authenticated client where practicable. Do not downgrade HTTP/service failures to success because expiry eventually makes the pool close.

This retains exactly the important dependencies: every original seat gets its return attempt before any reservation deletion; party cancellation follows its return barrier; membership changes are ordered by current revision; the leader remains available for cancel. Public Freestyle/FFA still have eight independent parties and can make progress independently after the return barrier. TimeRun/squad members share a serialized party mutation chain.

## Request budgets and calculated outer watchdog

Every actual HTTP keeps its current15s limit. A fixture request wrapper starts a new linked CTS immediately before that request, linked only to the dedicated cleanup watchdog/external teardown abort; CancelAfter(15s) applies independently. Never link cleanup to the already-cancelled gameplay lifetime, reuse a previous request's CTS, or give one15s CTS to a whole four-request leave stage. The production HttpClient/transport deadline remains unchanged.

With N original clients, a concurrency cap C=8, largest recorded party size M, and no extra HTTP reads beyond today's checks:

- Return phase: at most ceil(N/C) request waves when Expected exists, otherwise0.
- Cancel per party:2 serial requests.
- Leave per member:4 serial requests.
- Nominal HTTP critical path: `15 * (returnWaves + maxParty(2 + 4 * members))` seconds. Use0 for maxParty when no party exists.
- Proposed dedicated service watchdog: that calculated path +15s fixed continuation/scheduling allowance. This is an explicit fixture scheduling allowance, not a longer HTTP timeout. Timers/frame scheduling can still overrun expectations; any watchdog expiration is a failure.
- After watchdog cancellation, allow a separate bounded5s completion/abort drain. Record any unsettled task, request and unattempted dependent stage. Do not claim full attempts or clean disposal if the transport does not settle.
