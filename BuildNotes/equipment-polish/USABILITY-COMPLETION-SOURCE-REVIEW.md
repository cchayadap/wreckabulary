## Confirmed defect and bounded repair

The authored launcher opened a fresh course without inspecting its existing recovery file. Its non-default seed transaction changed `WorkshopHistory.Revision`; selecting a module also changes that revision. `WordboundWorkshop.Update` saved after one second, and the header's close action saved unconditionally. `WorkshopStorage.AtomicWrite` rotated the old primary into the single `.bak`; another save replaced that backup too. Manual **Recover autosave** then read the new primary. The separate `OpenTemplate` path recovered first, but it did not protect authored launcher entry. The input lane independently confirmed this source path before implementation.

The authorized fix adds `OpenAuthored` and an explicit **Recover draft / Use saved course / Back** choice only when that course ID already has recovery files. A clean entry sets the authored seed in the initial snapshot without an undo transaction or dirty revision. Pending choice blocks autosave, disable saves, preview and template switching; the normal header is not drawn. Back keeps the pending choice for reopening and leaves both files untouched. GUI button actions execute in Update, and focus loss/disable discards pending actions. The existing neutral-input gate is reused for controller navigation and reset on entry/exit.

Recovery preserves the exact saved seed/editor state. The storage reader now verifies that the recovered document ID matches the requested filename; a bad primary may use a valid matching backup. A changed draft on disk requires a fresh confirmation. Choosing the saved course first copies the current primary/backup into a uniquely named `recovery-archives` directory; any copy failure leaves the choice pending. Neither originals nor archives are deleted. This is an explicit user action, not routine source/cache cleanup.

Schema-1 recovery contains document ID/data and editor state, but no Unity asset GUID, item/rule assets or profile references. The chooser therefore identifies the course and recovered title/seed and explicitly says recovery uses the currently assigned catalogue/presentation and must be validated before playing. It does not infer that equal course IDs prove identical source/profile versions. No course asset or profile is replaced by recovery. Existing separate template/profile association is outside this bounded entry fix.
