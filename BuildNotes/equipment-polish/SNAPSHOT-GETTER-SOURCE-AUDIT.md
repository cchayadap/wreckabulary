# Snapshot defensive getters — bounded throughput source audit

STATUS: CONFIRMED REPEATED COPY SITES; no implementation, benchmark, compiler or native run

Inspected integration HEAD `c760861`; the reviewed Rules/Physics files had no working-tree edits. Scope: MatchStateValidation and its physical/thrown/defense helpers, plus `WordboundPhysicsWorld.ApplySnapshot`, `CanMove` and the related release lookup. Root's observed slow physical run motivates investigation but is not proof of the cost of any one site. No validation was removed or weakened.

## Getter contract and a ruled-out premise

`Scripts/Rules/Wordbound/EconomySnapshot.cs:16–18` exposes defensive collections: `Players` deep-copies every inventory, including slots, letter/reservation bags and optional craft; `Items` copies every ItemInstance; `Tiles` clones its entire value array. Each access also creates an array/read-only wrapper. Capturing a getter into a local avoids repeat copies for that access scope; merely changing a following LINQ query does not remove the copy.

**Current `MatchStateValidation.cs` itself already uses internal `PlayerStates`, `ItemStates` and `TileStates`, not those public defensive getters.** The per-body path builds item/tile dictionaries at lines 262–264. Resource validation builds a tile dictionary at 237 before its source/body loops. There is no repeated public Items/Tiles/Players getter in those loops to fix. The validation class is currently one source file; the separately named physical helper is `MatchStateValidationPhysical` in `MatchPhysicalValidation.cs`.

There are still repeated linear scans over internal collections—for example source-by-body matching at `MatchStateValidation.cs:244`, per-player deployment counts at 93, and per-mechanism item lookups at 411/416/435. These are candidates for local indexing if profiles justify them, but they are **not defensive-clone sites**. Do not describe them as allocating full snapshot copies on each scan.

## Validation boundary and implementation order

The lowest-scope first candidate is the trusted Rules helpers: replace defensive whole-collection reads with the already-existing internal state reads, without changing loops, predicates, failure messages or public getter behavior. That removes demonstrated needless copies while preserving the current public snapshot isolation contract. A separate Physics change can retain private copied dictionaries per accepted frame. Physics is in a different assembly, so do not make the internal arrays public or return mutable inventory/item references to arbitrary consumers simply to avoid copies.

`WordboundGameplayController.Reconcile:279` validates the frame before physics reconciliation; `WordboundPhysicsWorld.ApplySnapshot:116` validates again at its own boundary. There are further validation calls in authoritative restore and snapshot import. This audit **does not recommend skipping any of them**. Use existing profiling markers to quantify their contribution after removing repeated copy sites; a shared validated-context design would require a separate identity/immutability/error-path review.

For a bounded implementation, retain negative tests for malformed physical source/receiver, flight identities and held-defense state; keep defensive getter isolation tests; verify sequential accepted frames and a rejected frame cannot leave Physics with stale inventory/item indexes. Native movement, defense scaling, release and physical-puzzle paths must still run. Do not extend timeouts to claim an optimization pass.
