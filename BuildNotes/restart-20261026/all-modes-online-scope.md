## Why a menu change cannot complete the bridge

1. **Original lobby is blocked, not networked.** `LobbyMenu.Blocked` at line 697 blocks the entire legacy Matchmaking queue. `Go()` exits when blocked. Local `Launch()` at line 832 seats local input bindings and calls `Session.LoadMode`. `OpenWordbound()` at line 91 opens the separate `WordboundLobby` scene. `LobbyPages.ModesFor` at line 308 still displays a private-room card, but `Session.SceneForMode` has no `Room` case; simply enabling GO would not create or join a network room.
2. **Both client and service reject all five original IDs.** `Rules/Wordbound/OnlineContracts.cs:27` has an exact five-ID regex; `OnlineServices/src/model.ts:8` has the same five-value enum. Their capacity/team/fill logic is specific to those five. `Online/Client/WordboundPartyMenu.cs:13` exposes exactly the same IDs. Adding a button without updating both contracts will fail admission.
3. **Wordbound runtime is not a generic launcher for legacy scenes.** `WordboundLaunchAssets.cs:12` pins `WordboundGameplay.unity`; `WordboundLauncher.cs:85` constructs a `WordboundMatchClient`. `WordboundMatchClient.cs:30` requires `ModeDefinition`, `ResolvedCourse`, the canonical gameplay controller, network body prefabs and checkpoint authority. It does not start `RoundManager` or the original directors.
4. **Shared rule defaults do not transfer objectives.** `WordboundClientContent.cs:50` starts from `book.For("Dibs")`, then `ModeDefinition.CreateGameplayRules` overrides mode/team/downed/round/respawn/clear-out behavior. Its courses are the flagship or combat arena. This is reuse of movement/item defaults, not online Dibs gameplay.
5. **Original simulation is local and event/time driven.** `PlayerJoinManager.cs:61` constructs local bots; `:116` instantiates local `PlayerController`s. `RoundManager` evaluates local health states and changes `Time.timeScale` for slow motion. `ClearOutController.cs:23`/`:113`, `DeliverySpawner.cs:43`/`:54`, `MovingDayDirector.cs:175`, and `EscapeDirector.cs:259`/`:1269` use local time/randomness and scene objects. Host ownership, stable entity IDs, command deduplication, authoritative tick state and recovery snapshots must be added; replicating transforms alone is insufficient.
6. **Room codes bind Wordbound content and protocol.** `WordboundRoomInvite` at `WordboundPartyMenu.cs:474` carries `wb-room:<16hex code>:mode:format:region:protocol:seed:poolVersion`; it validates the exact current settings and `wordbound-v3`. The service's `QueueRequest` at `model.ts:25` distinguishes `QuickPlay`, `CustomFill`, `PrivateCreate`, `PrivateJoin`. A house-room invite must route to its matching runtime/content release; existing Wordbound codes cannot silently mean a local house mode.
7. **Public maps and saved state are explicitly versioned.** `WordboundPublicCourseCatalog.cs:97` enumerates nine mode/format variants per approved seed, covering only the five Wordbound IDs. The server checkpoint validator explicitly requires `wordbound-v3` and snapshot schema/canonical version 3 (`OnlineServices/src/checkpoints.ts:96`, `:118`); workshop bundles also require `wordbound-v3` (`bundles.ts:10`). A new protocol label alone does not make these validators compatible.

## Compatible implementation options

**Recommended: retain both gameplay families and reuse the online foundations through an explicit house authority adapter.** The existing `IWordboundGameplaySession` interface and `IWordboundFusionAuthority` seam (`Online/Fusion/WordboundFusionSession.cs:18`) make session/identity/connection reuse plausible. Introduce house-specific mode/content/state/controller types and saved house-online scenes. Extend the service with an explicitly versioned house checkpoint/content validator; keep the existing five-mode `wordbound-v3` protocol/catalogue valid. The present concrete `WordboundGameplayController` and snapshot types remain tightly coupled, so this is new adapter/state work, not a configuration switch. Prove one original mode end-to-end before sharing more transport abstractions.

**Alternative: port the five house objectives into a new revision of the canonical Wordbound simulation.** Reuse its body authority, inventory, command journal and migration logic, but add genuine round/revive/van/checklist/door-key policies and resolved house geometry. This can reduce duplicated simulation later, but touches the existing public snapshot protocol, content hashes and all five working Wordbound modes. It requires an explicit versioned rollout and regression matrix; it must preserve original gameplay rather than map Dibs to 10-knockout FFA.

**UI redirection alone is not an implementation option for this requirement.** Offering the newer modes as alternatives may be useful, but cannot mark the originals online. Likewise, merely enabling the old queue, sharing a seed, adding a NetworkObject to each legacy prefab, or weakening the checkpoint validators does not supply authority, mode outcomes or recovery.

Suggested delivery order: common house manifest/identity/interaction slice → Dibs full public/private round-to-three proof → Duos revive/team proof → Moving Out objective proof → Moving Day checklist/level proof → Escape randomized door/key/crew proof. Preserve each earlier mode as the next is added. This is an implementation proposal, not claimed completed work.
