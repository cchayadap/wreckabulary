## Binding-aware hints: one small dependency needs selection

Actual APIs are `KeyBindings.Display(InputAction, int=-1)` with effective override/localized physical-key fallback, `KeyBindings.Version/Changed`, `WordboundInputBinding.Revision/ActiveGamepad`, and `WordboundPlayerView.UsesGamepad`. The live automatic binding owns a **private separate** `DesktopBinding`; `PlayerView.binding` is also private. Global `ControlHints` reads `DesktopBinding.Shared`, which is not the live automatic instance and also includes unrelated couch/mobile controls. Creating another enabled map or reading the shared map cannot honestly guarantee the label matches the input actually consumed.

Therefore a true live-binding hint requires a narrowly approved extension outside the three visual files: a read-only prompt lookup on `WordboundInputBinding`, forwarded by `WordboundPlayerView`. It should return strings from the active existing desktop actions via `KeyBindings.Display`, or the active pad's actual controls, without changing/consuming input, refreshing device selection, exposing mutable actions or creating another map. Cache strings by binding/key version and actual device; unsupported injected test bindings should return generic text rather than guessed controls. If that scope is not selected, defer desktop rebinding-aware labels rather than hardcoding E/Q/Esc as universal.

With that accessor, the compact HUD can show `[Interact] Pick up · [Spell] Craft · [Menu] Menu`, plus held-item-specific `[Aim]+[Attack] Throw`, `Hold [Drop] Drop` and shield block guidance only when relevant. Existing action semantics stay unchanged. A source-confirmed wording correction is independent of the accessor: right-stick-click currently cycles equipped slots (`swap`), while pad Start opens the menu. Label these `RS: cycle gear` and `Start: menu`; do not imply RS opens the equipment menu. Keyboard Bag/Tab also cycles gear in this Wordbound binding.

Focused binding coverage should override Interact/Spell/Pause on the actual consumed desktop instance, check the displayed strings (including existing localized fallback), switch desktop↔pad and unplug, and prove reading hints changes no action state/revision. Preserve `WordboundInputBindingTests`, `LocalizedKeyBindingTests` and menu focus regressions. This is source/test planning only.
