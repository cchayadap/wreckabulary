# Wordbound interface theme grounded in the original game

STATUS: READ-ONLY PROPOSAL; NO IMPLEMENTATION, ASSET CREATION OR NATIVE RUN.

The actual Windows 220124 workshop smoke passed its five functional checks, but its equipment menu is still visually unfinished: gray translucent controls over the red avatar, low-contrast unavailable recipes, an edge overlapping the HUD, and generic gradient buttons. The returned workshop has contained map outlines and separated labels, but crowded palette rows and the same default control styling. Use the original UI's palette and type hierarchy to correct these specific gaps. Keep original GameHud, LobbyKit, fonts, artwork, ICY paths, camera, content and game behavior unchanged.

There is no current Wordbound UI theme profile or user UI-scale preference to claim is already editable. The existing camera/model profiles do not style IMGUI. Theme is client presentation, so it need not enter course documents, signatures, manifests, recovery snapshots or the input map.

## Proposed editable asset

Create `WordboundUiTheme` in a small shared `Assets/_Project/Scripts/UI/Wordbound/` folder, within the existing Wreckabulary assembly. Workshop already lives there and Online.Client already references it; no new assembly or dependency cycle is needed. Use a separate default asset at `Assets/_Project/Data/Wordbound/Authoring/Interface.asset`, referenced by a new `UiTheme` field on the existing Resources/Wordbound/LaunchAssets asset. Direct references retain it and its fonts in the player without adding another Resources collection.

Proposed **Assets → Create → Wreckabulary → Wordbound → Interface theme** makes copies reusable. The existing authoring setup creates/assigns the default only when absent, preserves custom assignments and rejects type conflicts. A small theme Inspector should expose four concise groups and a local sample of normal/hover/focused/disabled controls using the same styles. It must not open a scene or start gameplay.

| Inspector group | Bounded initial fields/defaults |
| --- | --- |
| Type | Existing Nunito-ExtraBold body Font and Nunito-Black heading Font; body about 15 px, heading about 20 px in the existing menu reference coordinates. Measure labels and fixed header constraints before adopting exact sizes; do not blindly enlarge every current hard-coded rectangle. |
| Colour | Opaque Panel `#FFF0D9`; Text `#173B3C`; muted text `#546763`; primary teal with cream text; secondary `#FFF7E8`; selected sage `#DEEDCF`; focus `#F08A4B`; disabled row `#EAD9B7` with dark muted `#4C5B5C`; error/notice from existing warm colours. Only the full-screen scrim is translucent. |
| Spacing | Panel padding, row gap, single-line minimum height, multiline/module minimum height and menu maximum width. Initial direction: 16–20 px padding, 6–8 px gap, about 34 px single-line rows and at least 48 px two-line module rows. Keep text measured so explicit custom values cannot silently crop content. |
| States | Flat normal/hover/pressed/focused/selected/disabled fills, a restrained 1–2 px border, small corner radius and visible focus outline. No shiny stock gradients, extra animation, decoration assets or texture noise. |

Opaque candidate colour pairs have nominal sRGB contrast approximately 10.84:1 (teal/cream), 5.35:1 (muted/cream) and 5.11:1 (disabled ink/fill). These are simple colour arithmetic, not measured rendered accessibility results: Unity's disabled tint, font rasterization and actual screen must still be inspected. Keep disabled controls genuinely noninteractive; never set GUI.enabled=true merely to improve their appearance.

No new player preference is necessary for this first repair. Designer changes live in the theme asset, are saved/undone through the Inspector, and never overwrite existing audio/graphics/control preferences. A future player text-size option can be a separate scoped task after layout acceptance; introducing a new global GUI matrix in the workshop now would risk pointer/viewport coordinate parity.

## Rendering and binding plan

1. Add one shared, owned `WordboundUiStyles` helper next to the theme. Clone the active GUISkin/styles without mutating GUI.skin or theme assets; resolve the raw Fonts once. Use a small bounded set of generated flat/rounded state textures (for example no more than 16 at 32×32), shared by all rows in that owner, never a viewport-sized upload or one texture per recipe. Cache between events. Rebuild only on theme/reference changes at the next Layout, keeping Layout and Repaint consistent. Release owned skin/textures on replacement, failure and destruction; do not destroy borrowed Fonts or the original skin.
2. Bind the launch theme to `WordboundWorkshop`, `WordboundMatchClient` and `WordboundLocalMatchClient`, then their HUDs. `WordboundLauncher` supplies the same client preference for assigned courses and templates. `WordboundCoursePlaytest` supplies `launch.UiTheme` for the Inspector route too. Optional new parameters must preserve current callers, with a deliberate default/fallback for existing fixtures. Do not attach the theme to source-specific content inputs or accidentally restore a different theme when switching templates.
3. Apply the cloned skin in each Wordbound owner's OnGUI inside try/finally, restoring skin, colour/background/content colour, GUI.enabled and GUI.matrix. Explicit heading/wrapped/selected/overlay caches must rebuild with it. Retain scope around early recovery/share/online-preparation branches. Original game screens and other OnGUI owners must see their original GUI state afterward.
4. Give equipment/crafting/journal one opaque light card, dark readable text, clear primary Resume and secondary Return, flat recipe rows and a distinct selected/focused state. Keep current labels, control names, event order, search buffer, scroll behavior, item filtering, commands and deferred action execution. Online simulation does not pause just because this menu is open; do not relabel it “Paused.”
5. When this menu is open, omit only the passive top/bottom HUD panels to eliminate overlap; retain relevant fault, waiting and terminal-result information inside the card so hiding the HUD cannot hide a connection failure or result. Preserve the existing 1280×720 scale convention and clamp the card to the available area. The world, story objects and camera remain unchanged.
6. Use the same opaque panel/text/flat-control vocabulary for workshop chrome and its recovery/share/online panels. Give two-line module buttons a measured multiline style/height instead of the existing 27-pixel action minimum. Keep viewport coordinates, map textures, clipping, outline colours, pointer drag/pan/zoom math, course editing, autosave/recovery and Undo untouched. This is a skin and bounded control-layout correction, not a new editor navigation system.

Likely production touch points are the two new shared UI files; LaunchAssets; Launcher; MatchClient and LocalMatchClient; MatchHud/MatchHudMenu; Workshop/WorkshopInteraction cleanup; AuthoringSetup; and CoursePlaytest. The theme Inspector is a new Editor-only file in the existing Authoring.Editor assembly, which already references Wreckabulary. Only update additional cached workshop style fields where needed to prevent stale styles. Root creates assets and metadata through Unity; no handwritten .meta or changes to original GameHud/LobbyKit are part of this plan.

## Acceptance before calling this improvement complete

- Source/native checks: GUI state restored across normal and exceptional exits; original skin/Fonts unchanged; repeated open/close and theme replacement release owned native textures/skin; invalid numeric/colour/font inputs report clearly; no per-row/per-frame texture creation. Inspector defaults survive save/reload and custom assignments survive setup rerun.
- Existing menu Layout/Repaint, gamepad focus, one-shot actions, text input, menu-close/device-loss and workshop recovery/navigation tests must remain green. Add only focused theme lifetime/state-restoration and measured long/two-line label cases. Do not replace these behavioral checks with colour-only assertions.
- Actual visible Windows 1280×720 captures should repeat the same 220124 menu/workshop route and show opaque readable panel, legible disabled recipes, identifiable focus/selection and no HUD overlap. Include one long title/recipe, a two-line palette module, keyboard search, controller selection/scroll, and recovery/online-preparation modal. Check a smaller supported window for clipping and usable scrolling; do not claim universal scaling from one image.
- Reuse the ordinary Unity Inspector to duplicate/assign the theme, change a colour/font/row size, save/reload and observe the next playtest without coding. This is the concrete no-code design acceptance. The user still decides whether the result matches original quality; source checks and the existing 5/5 smoke are not visual approval.

No UI, runtime, asset, scene, kit or preference change was made for this proposal. Camera composition, large avatar, world dressing, replacement equipment art and a broad uGUI migration are separate from the requested minimal repair.

Independent input-lane design review reinforces the implementation boundary: retain deferred Update actions, stable Layout/Repaint control tree and keyboard-control names, pointer/pad provenance, neutral gates, exclusion of disabled controls from pad focus, the search typing lease and fault/result/Back escape routes. Do not conceal underlying interactive controls with alpha zero; menu ownership must also remove their interactions coherently. Theme replacement cannot mutate shared GUI styles or original assets. Actual disabled tint and focus appearance require rendered acceptance. This is design feedback, not review of implemented source.
