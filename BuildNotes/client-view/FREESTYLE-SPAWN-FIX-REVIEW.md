## Confirmed scope and additional paths

Online's audit is accurate about constructor ordering, anchor limitations, floor openings and exact snapshot restoration. `InitializePractice` runs before map props/resources/fixtures are added, so a constructor check of only the current `bodies` dictionary cannot establish static clearance. `CourseGeometry.ValidateLocation` requires the authored module floor Y and an X/Z margin; runtime `BuildFloor` can still subtract a stair/ramp opening there.

Two additional source paths matter:

- `AuthoritativeMatch.Apply(DropKeepsake)` sets the active loose body to the carrier's exact `origin.Position`. This can recreate the same overlap in both Freestyle and race modes. It is not solved by changing the constructor. A full keepsake-placement correction must either cover this explicitly or leave it recorded as a separate defect; do not quietly broaden a Freestyle patch into all race handling.
- `Synchronize` sends any active nonplayer/nonplatform body below the course to `course.RecoveryAnchors[0]` when it lacks a source. That includes a free keepsake and bypasses `PracticeRecoveryPosition`. It also assumes a nonempty anchor collection. A Freestyle recovery fix must route this case through the same safe selection rather than retain a hidden first-anchor fallback.

The ordinary generation recovery path is not a free-form retry point. `MatchProgress.AdvanceCore` clears the due timer and increments the team's generation before `UpdateKeepsakes`. Snapshot validation requires body/team generations to match and rejects a recovery timestamp at or before the current tick. Returning the old generation, throwing every time a candidate is occupied, or leaving an expired timer would violate existing behavior or validity.

## Smallest implementation boundary to select

The recommended first geometric implementation is an internal, deterministic **authored-anchor selector**, rather than a general procedural placement/search framework. Prefer eligible anchors in the starting module for initial/no-site placement, and the selected site's module for selected recovery; then use the same validated starting-module fallback. Use ordinal IDs for ties, no RNG, no input/physics mutation. Choose only at creation, drop/recovery events, not during ordinary ticks or restore.

For each candidate, require the whole upright keepsake volume (with a documented contact clearance) on supported floor, within the module, outside declared start/respawn capsule volumes, resolved static prop bounds, supplies and moving-fixture envelopes. Account for actual floor cutouts; rejecting an intersected opening conservatively is sufficient for a bounded first implementation and must be labelled as such. Preserve vertical separation so objects on another floor do not reject a candidate. Do not treat authored Path/Recovery reservations as physical solids: valid flagship paths and anchors overlap intentionally. Derive or parity-test shape dimensions against the actual `.6 × 1.8` capsule and `.45` keepsake box, rather than introducing unrelated magic dimensions.

At runtime, also reject overlap with relevant active canonical actors/objects, excluding the keepsake itself. Static candidate construction can be cached for this immutable course, while current occupancy must be evaluated at the actual event. Declared starts remain reserved even for seats not currently occupied. This keeps a later arriving player from spawning inside the initial keepsake.

For a new match with no supported safe authored candidate, return an actionable preflight failure before spawning native bodies. Preserve the old course/draft for editing. No anchor search, silent offset or document rewrite is needed for this bounded option. It deliberately does not promise that every previously accepted anchorless/overlapping map can launch unchanged. If root requires that compatibility, a separate bounded search with identical geometry predicates is needed; do not add it speculatively.

## Blocked recovery needs one explicit policy decision

An occupied preferred anchor should try another already validated candidate first. If **all** candidates are occupied, a robust correction cannot simultaneously promise immediate recovery, no overlap and no behavior change. The recommended extension is to postpone the recovery transaction until a candidate is clear, keep the same keepsake/generation, and retry with a future timer; do not consume the generation before placement succeeds. This requires a narrow progress/authority coordination point before `RecoverKeepsake`, and a testable pending-recovery policy. A timestamp of `current tick + 1` can use the existing serialized timer and satisfies current validation, but would be a deliberate blocked-recovery behavior change, not a purely geometric two-line fix. The normal unblocked 600-tick deadline stays exact.

The below-course path and unavailable drop also need explicit treatment: an unsupported falling keepsake cannot be left to fall indefinitely while waiting, and a requested drop can safely return `BlockedPlacement` while retaining its carrier, as ordinary item releases already do. How an already out-of-world keepsake is held pending recovery must be selected and validated before implementation; do not synthesize an inactive state merely because current loose-body validation happens to permit it. This report does not authorize that state-machine extension. If root chooses an initial-only correction first, mark recovery/drop acceptance incomplete rather than claiming the whole defect fixed.

## Restore and compatibility

`RestoreState` replaces the exact saved body poses and practice state. `RestoreCommitted` verifies the durable identity/hash and next epoch, then restores; it does not call the placement selector. Preserve this behavior, including an old snapshot's historical overlap. Do not add a universal snapshot nonoverlap invariant: native contacts, carried relationships and historical poses are legitimate imported evidence.

`WordboundGameplayController.Initialize` constructs a new `AuthoritativeMatch` before restoring the committed state. A constructor-only new-course preflight would therefore also reject some old course restores before their valid bodies are read. A robust implementation must distinguish new initialization from restoration without bypassing existing binding/content/snapshot validation; a narrowly scoped restore factory or deferred new-match preflight is preferable to catching and ignoring the constructor failure.

No snapshot field, codec/canonical version or protocol version change is inherently required for selecting a different valid free-body position. Do not bump those versions as part of the geometric repair. My earlier equipment report recommended a practice-policy hash change conservatively; this review narrows that recommendation: a positional bug fix does not by itself prove a hash/version migration is necessary. An explicit new pending-recovery semantic or stronger content-eligibility policy needs a deliberate release/mixed-build decision. `WordboundPracticePolicy.Hash` feeds Freestyle's mode identity (and authored Explore plan identity), so changing it has real admission/content consequences and should not be automatic. Exact saved snapshot hash/pose restoration remains required either way.

### Deferred initial failure is feasible, with precise guards

The current orchestration supports this narrower compatibility choice without a restore factory or universal validation bypass:

1. Finish constructing all canonical bodies and the existing validated snapshot, then run the deterministic initial-placement selector. Preserve every existing constructor `EnsureValid` check. If there is no admissible candidate, retain the structurally valid placeholder only in this unstarted authority and store a private, nonserialized unresolved-initial-placement condition.
2. Reject `PublishSnapshot` while that condition remains. Also reject direct `AuthoritativeMatch.Advance`, because public engine-free callers can otherwise advance before their first publication. Do not silently return an apparently successful pending publication or turn this into an indefinite startup wait.
3. Local startup calls `WordboundLocalSession.MarkLocalReady → CommitCheckpoint` before setting GameplayReady or raising GameplayStarted. Online `BeginAfterCheckpoint` publishes the bootstrap and completes its barrier before setting readiness/raising Begin. `WordboundGameplayController.BeginHost` requires both GameplayReady and a committed mark before composing native bodies. Thus this failure can occur before gameplay body composition, even though the local/network Runner and static scene may already exist. It is not a claim that no Runner was allocated.
4. A restored online host follows `RestoreWriter → Download → bridge ValidateSnapshot → RestoreCommitted` before its new gameplay start. Only after the complete existing durable binding/hash/epoch validation and successful restoration may the private initial-placement condition clear. A failed restore leaves it set. Do not clear it in general `RestoreState`, which also serves transaction/tick rollback, and do not rerun new-course placement over an accepted legacy pose.
5. `CreateLocal` performs an initial capture/export/import before local publication; that full validation remains. Remote clients can retain their unused constructor placeholder while displaying validated received frames; a later host must actually restore the durable authority before it gains publication rights. No received mark or ordinary client callback should clear the authority's private condition by itself.

This permits exact valid legacy snapshots from an anchorless/newly ineligible course to restore without permitting a brand-new unsafe launch. It deliberately preserves a legacy overlapping pose at restore; the fix prevents new placement events and cannot also promise to rewrite historical snapshots invisibly.

### Smallest complete event policy

Use one Freestyle-only selector with immutable static candidates and fresh event-time occupancy, shared by initial creation and generation/below-course recovery. Existing race placement remains outside this patch. Initial candidate choice must run after canonical composition, or use complete resolved placement/supply/fixture geometry even though those bodies have not yet been added.

Authored anchors are sufficient as the first implementation boundary for the demonstrated content: equipment Room/Safe is `(0,0,-5)` versus player Start0 `(0,0,-1.2)` and letters at z=-3; default Freestyle StartSafe `(0,0,-6.5)` differs from starts at z=-8. These coordinates are not execution proof, but refute the assumption that a general procedural search is necessary before attempting the fix. Require real resolved-course selector tests for equipment/default/flagship; only add a bounded deterministic nearby-floor fallback if those tests or explicit compatibility requirements demand it. All-invalid new courses should fail clearly, retaining their editable draft.

Due recovery needs an authority decision **before** `MatchProgress.RecoverKeepsake` consumes the timer/increments generation. At the original 600-tick deadline, choose a currently safe candidate and complete recovery atomically; otherwise retain the generation and defer the existing timer to a strictly future tick. A narrow internal host-advance decision/explicit deferred-team set is preferable to a public trusted skip flag. It must use the current command/pose/practice selection after those existing operations, preserve all race behavior, and be cleared/restored on tick failure. Reserved start volumes cover players that respawn later in the same transaction.

For all-candidates-busy or below-course-with-no-space, explicitly park the same loose keepsake as **inactive and kinematic**, at its existing bounded canonical pose, with zero motion and a future recovery timer. This avoids creating an invisible solid at an occupied anchor. Keep its identity and generation until successful placement. The existing fields can represent this state; tests must establish its intended behavior rather than merely observe that today's validator accepts it. `UpdateKeepsakes` must preserve that pending inactive state instead of blindly setting active whenever carrier is null. The generic below-course loop must not subsequently route it to anchor[0]. A retry cannot leave an expired timer, increment a generation every blocked tick, fault/roll back repeatedly, or spin on wall time. This is a deliberate busy-recovery policy extension; the normal unobstructed deadline is unchanged.

Explicit Drop is separate from recovery relocation: it must use bounded nearby floor-supported placement with clearance/path checks, and return `BlockedPlacement` while retaining carrier/timer/body if none is available. It must not teleport a dropped keepsake through a wall to a distant recovery anchor. The existing pure item release candidate geometry may be reused where appropriate, but actual `WordboundPhysicsWorld.TryRelease` currently rejects every non-Item and requires an economy held entry, so calling it for a keepsake is not a working implementation. Any needed read-only world query must be deliberately scoped; no pose/physics injection.

**Additional mandatory release paths:** `MatchProgress.Disconnect`, `Return`, `RecoverPlayer`/Fell and knockout also clear the carrier. `AuthoritativeMatch.Disconnect` invokes `UpdateKeepsakes` outside Advance; the other paths can release during a tick. A fix limited to explicit Drop and generation mismatch will still reactivate the carried body at its old player's foot. Detect or explicitly route each just-released transition: safely place nearby when allowed, otherwise park it inactive for its existing recovery schedule. Disconnect/return/fall itself must not fail solely because all destinations are busy. Distinguish a just-released body from already-pending recovery so repeated `UpdateKeepsakes` calls do not bypass the deadline or reactivate it. Existing transactional rollback must restore the complete observable state.

### Geometry contract and concrete blockers

- Match the upright .45 m keepsake box and .6 ×1.8 m player capsule/foot convention used by GameplayPlan/GameplayBody. Reserve every authored Start/Respawn volume, not only current roster occupancy. Use explicit small contact clearance and native parity tests.
- Support means the complete footprint lies on the actual floor at that level, not just `module.Bounds.Contains`. Runtime BuildFloor subtracts Stairs/Ramp openings using floor thickness/headroom and ordered endpoints. A conservative exclusion is acceptable if it contains every actual cutout; test both slope directions, upper/intermediate floors and touching edges. Do not classify another floor's object as a blocker by X/Z alone.
- Resolved static props need approved dimensions and authored yaw; moving fixtures need their complete reachable envelope, including inactive/gated future positions. Supplies and other canonical collision bodies need their actual shape convention. Arbitrarily rotated current native bodies require a conservative correctly transformed volume, not an unrotated half-size assumption. Reject unknown/invalid dimensions rather than accept a false clear placement.
- Reuse only immutable static metadata. Current occupancy, current mutable item dimensions and selected practice site are read at the event; never cache a successful empty-space decision across ticks. Ignore the same keepsake and noncolliding inactive/held bodies, but retain actual player/object blockers. Do not use Path/Recovery reservations as solid walls.
