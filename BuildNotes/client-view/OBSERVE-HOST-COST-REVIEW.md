# ObserveHost cost review

STATUS: READ-ONLY AUDIT COMPLETE; proposal only, no implementation or jobs. Root requested one bounded candidate from the actual 003140 ready observation: 742 calls / 2177.385 ms inclusive elapsed, approximately 2.934 ms/call. This scope is not exclusive CPU and does not establish removable cost or FPS.

Source trace: GameplayController.AdvanceHost validates completed pose coverage then invokes options.ObserveHost. PuzzleRuntime.ObserveHost rechecks current host/frame/rules and exact pose IDs, refreshes current scene collider ownership, then visits unfinished teams and physical sites before progress sensors. Authored observation performs a full frame.Mechanisms.Single scan for every visited site before solved/active filtering; TimedMechanism later queries that same site's previous mechanism again. These are immutable snapshot records, while collider/Rigidbody/admission/rules evidence remains live.

Current candidate to investigate: lazy per-invocation grouping of mechanism records keyed by exact(Team,Lap,PuzzleId), retaining queried-key Single predicate exceptions and original team/site/output order. Construct only at the first original lookup after RequireHost/pose/RefreshColliders checks; do not use eager ToDictionary duplicate rejection or move physical-phase checks. No across-call cache, contact reordering, stage/evidence change, live collider cache, fingerprint skip or authority-validation removal is proposed. Need complete mutation/error-order proof and meaningful old-query parity plus native evidence before recommending implementation.

## Bounded candidate and semantic boundary

Read source at integration `e34293a2bee931bde5760738ab2bbfa48610f605`, with actual timing from `native-public-delta-20261024.json` / XML `editmode_20261024T003140Z.xml` on `59682248`. The later root state includes Synchronize changes; this report does not transfer the earlier measured cost to that later build.

`WordboundPuzzleRuntime.ObserveHost` lines 107–132 calls `WordboundAuthoredRuntime.ObserveAuthored` for each unfinished team. Its line 188 mechanism query precedes solved/active checks, and successful predicate `Single` scans the whole frozen collection. The flagship source/tests establish 72 physical sites; this actual TeamSolo frame records 432 mechanisms. With both initial teams unfinished, the source therefore implies 144 such queries and 62,208 mechanism predicate evaluations per observation, before any optional second CLOCK query. These are derived loop counts, not instrumented timings. A lazy per-call ordered lookup could reduce repeated scans while adding one bounded grouping allocation; the net cost must be measured.

The candidate is confined to the post-physics ObserveHost call and its authored helper. Build a lookup of exact `(Team, Lap, PuzzleId)` at the first original mechanism query; preserve the original query positions. Resolve a group with the predicate overload `Single(m => true)` so empty/duplicate queried keys retain the original exception type/message. Do not pre-reject duplicates with `ToDictionary`, change team/site/output enumeration, skip inactive sites before their original query/phase check, or reuse a prior call's index. The optional CLOCK second lookup can use the same per-call index at its original location. Legacy socket observation can remain unchanged in the first slice.

`MatchSnapshot.Freeze` owns a non-null read-only array; `MatchMechanismState` and its physical evidence expose immutable values. External mutation of the constructor input cannot change that array. Indexing these scalar keys reads no user callback or live Unity property. `RequireHost` and the potentially externally supplied content validation run first, followed by exact pose-set validation and live collider ownership refresh. Leave these checks ahead of lookup construction. `ObserveAuthored` then performs live body, admission, recipe, collision, support and sensor queries synchronously; their order and operands must remain untouched. The lookup never caches those dependencies, rules, catalogue, fixture phases, `controller.Frame`, or a validation result. A new frame/call always needs a new index. The analogous scan in `MoveAuthoredFixtures` is before physics and outside this measured scope; do not bundle it into this proposal.

## Required proof before accepting an implementation

- Exercise the actual production lookup with a valid multi-team/multi-lap snapshot, exact returned reference/order, queried missing/duplicate keys, an unqueried duplicate, and replacement snapshots with changed solved/motion state. Compare exception type/message against the original predicate query, including earlier versus later queried faults. If direct test accessibility requires an internal bridge, request that narrow scope; do not mutate controller private state or test only a copied algorithm.
- Retain native all-six-family progression and focused CLOCK/fixture ordering checks. Verify repeated observation of the same unadvanced frame and the next actual frame preserves full emitted mechanism/progress evidence and does not change canonical state. Existing malformed pose/current-frame/missing phase rejection must remain earlier than the first lookup wherever it was earlier before.
- Measure the production helper against the original query sequence on the same actual flagship snapshot, including construction, valid output/reference parity and allocations. Then use the existing ObserveHost/HostStep phase windows on a matched native or Windows case; no extra per-contact instrumentation is needed. Report workload/call counts and allocation cost, not an assumed FPS gain. All 2177.385 ms includes fingerprinting, collider refresh, other lookups and physical queries, so it is not a savings estimate.
