# Native gameplay CPU recorder

STATUS: BOUNDED SOURCE REVIEW PASS by recover_online; native execution pending. No Unity/compiler/heavy job run in this lane. This is opt-in diagnostic instrumentation, not a performance acceptance result.

Set `WORDBOUND_PROFILE_NATIVE=1` only on the coordinator-owned diagnostic job. Existing online gameplay gates and the physical puzzle gate remain required. With the variable absent, no recorder is constructed. Both fixtures start recording after their existing EnterPlayMode transition and lifetime creation, before content/session/controller startup. Teardown stops and reports before runner/service cleanup, including after an assertion failure. No yield, timeout, operation order, gameplay predicate or production setting changes.

The two existing native test assemblies have no shared test-helper reference. Each receives the same small assembly-local `WordboundNativeProfiler` implementation, with only namespace differing. This intentional test-only duplication avoids new assembly dependencies/cycles, runtime helpers or kit edits. Only three hook lines are added to each existing fixture (field, start, teardown). Root owns generated metadata.

Each recorder targets one exact `ProfilerCategory.Scripts` marker: `WB.Match.Reconcile`, `Capture`, `Advance`, `Validate`, `Presentation`, `PhysicsApply`, `BuildWorld`, `BeforePhysics` (all use the `WB.Match.` prefix). The producer scopes are owned by recover_online. Consumers register the same names without emitting any Begin/End samples, so missing/unexecuted instrumentation cannot manufacture a duration. Validity alone is insufficient: no invocations, unexpected units, invalid sample values or a start/stop/read error produce unavailable evidence.

Options are explicitly main-thread only, sum samples within each frame, and wrap at 32,768 retained frame samples per marker. No per-frame managed polling, array copy, log loop or cumulative summation is introduced. All recorders stop before any report is formatted; arrays are read once at teardown, then every recorder is disposed in a finally block. Per-recorder errors are labelled with phase and exception type, without response text, identities or credentials. Recording does not survive a domain reload; fatal termination/reload can prevent a report and is not evidence of zero cost.

`WORDBOUND_NATIVE_PROFILE_WINDOW` identifies the case, start/end engine frames and monotonic elapsed seconds. Each `WORDBOUND_NATIVE_PROFILE` line reports validity/unit, retained frame sample count, sum of invocation counts, captured total CPU milliseconds and maximum **aggregated frame** CPU milliseconds. The maximum is not an individual call maximum. Inclusive parent/child and recursive scopes overlap, and all controller instances on the main thread contribute; do not add scopes together or interpret their total as elapsed wall time, per-peer cost, rendering/GPU time or end-user Windows frame rate. The final incomplete frame may be omitted, explicitly disclosed without inserting a new yield to flush it.

Capacity and WrappedAround are reported per marker. On wrap, the totals/max cover only the retained tail and the overwritten sample count is unknown (at least one); no complete-case total is claimed. Without wrap, the output only states no buffer wrap was observed, not that the final partial frame or uninstrumented work was captured. Zero observed invocations print unavailable timing fields. The fixture's ordinary pass/fail verdict remains independent of this diagnostic availability.
