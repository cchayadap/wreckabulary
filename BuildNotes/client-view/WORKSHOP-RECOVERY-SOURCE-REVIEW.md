# Workshop recovery source review

STATUS: SOURCE PASS for the bounded authored-draft preservation repair at `27042b5`. Read-only production review; native and rendered/controller tests not run.

Scope: existing, damaged and mismatched authored drafts; open/cancel/disable/template/autosave behavior; input focus; current source bindings; explicit replacement and archive boundaries. The reviewer owns only this report.

The baseline defect is confirmed: `WordboundLauncher.OpenWorkshop` opened fresh authored content without recovery, then applied the authored seed. A nondefault seed or selection changed `WorkshopHistory.Revision`, permitting autosave to replace the existing primary. Header Back to party/Close also saved unconditionally. A subsequent save could rotate away the old backup.

The repair uses `OpenAuthored` to initialize seed without an edit, and presents a recovery choice before normal workshop controls become reachable. Pending choice returns early from Update, OnGUI and OnDisable, and guards Open/OpenTemplate/Preview. Back leaves the choice pending and retains both recovery files; reopening restores the choice. Recover restores seed/editor selection with a fresh undo boundary, re-reads the file before accepting it and requires another confirmation if it changed. Invalid or mismatched course data cannot be recovered; a valid backup remains eligible.

Use saved course is an explicit replacement choice. `ArchiveRecovery` copies the primary and backup into a unique subdirectory of the configured `recovery-archives` folder before editing is enabled. Course IDs are restricted to 1–48 ASCII letters, digits, underscores and hyphens, and no source recovery file is deleted or moved. A failed copy keeps the prompt pending and leaves originals intact. Even if recovery changed while the dialog was open, this replacement choice archives the current on-disk bytes; the recover choice separately refreshes its displayed snapshot before confirmation.

Input handling preserves the deferred IMGUI action pattern: buttons queue decisions, and Update applies them. Focus loss clears the queued decision, including the actual OnApplicationFocus callback without an intervening unfocused Update. Existing `WordboundPadFocusGate` suspends held actions and requires neutral on entry, focus/typing/blocker transitions and device changes. No controller action is queued across frames; pointer choices remain intentional actions. Recovery UI uses cached labels and a scroll view. The existing view is inactive while the choice is pending.
