# Flagship canonical body budget

STATUS: SOURCE AUDIT COMPLETE — WHOLE-MATCH BUDGET BLOCKER

The current `WordboundReconciliationPlan` rejects more than 512 canonical bodies, including inactive bodies. This audit does not raise that limit.

The focused budget fixture creates the real flagship, resolves the exact selected mode, constructs a real `AuthoritativeMatch`, imports its canonical snapshot and passes that snapshot into the actual reconciliation planner. No Unity or physical sensors are involved; the world-query implementation refuses interactions. All five budget cases passed, within the 24/24 focused source gate. Evidence: `focused-schema2.log`, `body-budget-results.log`, local TRX `TestResults/focused-schema2.trx`. This linked the puzzle owner's frozen full Rules and gameplay planner source, including canonical per-team moving fixtures.

The separate three-lap estimate counts each supply scope whose prerequisites can be satisfied in its selected lap, plus the initial non-tile bodies and one spent crafted body per required puzzle and team. It describes a slow traversal where unlocked renewable supplies have refilled before leaving a lap. Existing authority retains old-lap tiles and spent item bodies. It also reports the additional letters from breaking each marked TABLE if those letters are left unused.

This is a scenario estimate, not an observed complete playthrough or a universal upper bound. Optional crafting, repeated recovery, destruction, deployment expiry and extra replacement tools can add bodies. Freestyle has no match duration or lap bound that makes repeated crafting finite. A startup PASS therefore cannot establish whole-match compatibility with the 512-body runtime budget.

The scenario exceeds 512 even for one-player TimeRun. The root owner received the result before native flagship integration. This content is validated for layout/startup, but whole-match runtime readiness remains blocked on a deliberate body/resource lifecycle decision and regression coverage. Raising the cap alone would not bound an unlimited Freestyle session. No cap, economy, source retirement, snapshot, or runtime behavior was changed in this audit.
