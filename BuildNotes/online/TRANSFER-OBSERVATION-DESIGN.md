Question: when a matching snapshot transfer reaches the existing absolute 10,000 ms age limit, how much was queued, which chunk callbacks ran, and how much local monotonic time elapsed? The 191029 public run reached gameplay but rejected a matching, nonduplicate chunk at 15,117 ms. Existing facts do not reveal packet size, chunk index/count or received progress; the failure is not proof of packet loss or mixed snapshots.

## Current boundary and missing facts

- `WordboundFusionSession.cs:704–711`, SendCommitted: one immutable local packet/mark is captured, `sentMarks[player]` is installed, and every chunk is synchronously encoded/queued. No enqueue count, packet length, local queue span or ACK span is retained. Send returning proves only that the SDK call returned, not physical transmission or reception.
- `Session.cs:839–848`, OnReliableDataReceived: current-run checks precede OnlineFusionWire.Decode. That decoder validates the JSON, mark, count/index/length and decoded base64 size before ReceiveSnapshot is called. A timestamp only inside ReceiveSnapshot would omit this decoder cost. No transport arrival timestamp is exposed here.
- `Session.cs:713–737`, ReceiveSnapshot: first chunk sets `incomingStarted` using the existing wall clock. Later chunks test the original mark/count/length/hash, absolute age and duplicate conditions, then decode/store a chunk. The completion scan, packet restore/full hash verification, authority validation, ReplicaReceived event and ACK all follow. Existing diagnostics cannot say whether the rejected chunk was the final missing chunk or the second of many.
- `Session.cs:739–755`, SnapshotTransferError and `:788–796`, FailureFacts: fixed numeric allowlist already exports same-field/duplicate booleans, UTC age and the unchanged limit. It does not expose content or keys. This is the narrowest failure-only extension point.
- `Session.cs:860–864`, exact SnapshotAck: the stored mark is verified before removal, event delivery and optional next transfer. This is the valid end of a sender-observed ACK span. `OnReliableDataProgress` is empty; using that callback would require separately establishing its SDK semantics and correlation, so it is excluded from the first proposal.

OnlineSnapshotPacket permits at most 64 chunks of 4096 bytes and 262144 compressed packet bytes, including its header; raw snapshot maximum is 8388608 bytes. Packet.Length is compressed packet size, not JSON/base64 wire bytes. Do not encode, decode or hash a second time just to measure size.
