## Protocol to implement

All new endpoints are authenticated POST /v1/pools/{poolKey}/matches/{matchId}/{action}. Identity comes exclusively from the existing guest access credential. All checkpoint rows live in the existing MatchPool SQLite DO, separate from its JSON pool row, so Return, writer fencing, head CAS and checkpoint mutation share one transaction.

- checkpoint-claim: {claimId(UUID), reservationGeneration, rosterHash}. Only a STARTED, nonreturned, reconnect-eligible seat may call. Before the first claim, caller must equal the first player in the signed roster array. This exact selection also drives initial Photon Host versus Client. Claim creates a distinct monotonic writer term with 15s exclusive expiry. A live term cannot be preempted by any actor. Expired/terminal prior writer permits a new claim. Reusing an expired/retired claimId fails. Same live claim replay returns its existing term without extending expiry. Claim atomically returns term, assigned gameplay epoch and exact committed head.
- checkpoint-renew: {term}. Only the same actor and original nonexpired term renews. Expiry is exclusive: now >= expiresAt is invalid. A new claim is required after expiry. Gameplay epoch is 0 with no committed head, otherwise previous committed epoch + 1 on a new term. Renewals and failed claims never increment the gameplay epoch.
- checkpoint-begin: immutable {uploadId(SHA256 of manifest excluding uploadId), term, previousHeadId|null, stamp:{matchId,identityHash,epoch,sequence,tick,stateHash}, wireHash, rawLength, totalBytes, chunkCount}. Exact pinned match/roster/content binding is computed server-side. Bounds: packet <=256KiB, raw <=8MiB, 4096-byte chunks, <=64 chunks. At most two incomplete uploads per match, 60s TTL. A retry of the same manifest is idempotent; changed manifest is rejected.
- checkpoint-chunk: {term,uploadId,index,data(base64url)}. Exact immutable chunk length/index checked. Retry of identical bytes succeeds; replacement fails. Actor, term, lease and match lifecycle checked in the same transaction.
- checkpoint-finalize: {term,uploadId}. Server reconstructs all chunks, verifies wire SHA256, bounded raw inflate, raw SHA256, strict UTF8, snapshot schema2/canonicalVersion2, envelope hash, exact binding/seats and stamp. The final transaction rechecks actor, term, expiry, terminal state and exact previous-head CAS; sets head only after complete validation. Receipt contains exact manifest/head. A lost response can replay the same committed upload while its writer term remains valid. HTTP response is behind the DO durable storage output gate. No command acknowledgement precedes this exact receipt.
- checkpoint-head: {} returns current complete head and prior complete head metadata for an eligible seat. checkpoint-read: {uploadId,index} returns immutable bytes only for current or prior committed head. Partial uploads are never readable through the committed interface. New host claims before reading; old writer is fenced and cannot evict the claimed head while it is restored. Readers of older diagnostic heads must restart if retention advances.

The first commit under a term uses its assigned gameplay epoch and exact head returned by claim. Further commits retain that epoch and advance sequence/tick monotonically. The assigned epoch is distinct from writer term, so failed takeover claims cannot skip domain epochs. With an empty head, only epoch0 bootstrap is allowed; there is no invented prior gameplay to restore.

Retention: current and previous complete heads survive partial uploads; uncommitted uploads expire after60s. Per-match bounded claim receipts and upload count prevent unbounded orphan growth. Match deletion removes all checkpoint rows. Terminal Return denies claim/renew/upload/finalize immediately in the same DO.

Session ordering: verify signed match and Photon identity; initial host is deterministic signed-roster[0]; replacement comes from Photon election. The elected host claims writer independently of domain admission-ready, downloads the claim's complete head, validates through real MatchSnapshotCodec and restores at assigned epoch, then authenticates/adopts seats and verifies fresh scene readiness. Signed connection authorization remains separate from writer ownership. Tick advance/publish require a nonexpired writer term, and failure preserves the previous committed state. Photon migration data becomes only a minimal election/bootstrap marker; its success never acknowledges canonical gameplay.
