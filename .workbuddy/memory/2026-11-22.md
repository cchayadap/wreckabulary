## Boss Fight — spelling regression fixed
- Bug: in BossFight, `BossFightDirector.Restart` set `Summoner.WordsOverride = names.SpellWords()` where `SpellWords()` returned only CALC/ULA/TOR + ZAP/BEES/MAGNET. That removed BAT and every other recipe from the wheel and from `Recipe()`/`StartsRecipe()`. Typed `SubmitComposer` also required an `items.json` entry via `GameHudCards.EnabledRecipe`, so shield words could never be typed even though the wheel path had `SignalWords`.
- Fix: `BossNameCatalogue.SpellWords()` now returns the full enabled catalogue + shield words (never a replacement list); late joiners get the same list via `BossFightDirector.SetWords`. Added `Summoner.IsSignalWord` / `Summoner.CanCraft` as the single craft gate; `GameHudCards.EnabledRecipe`, `SubmitComposer` and `TypedStatus` now accept signal words without an items.json recipe or gear slot while still checking health/dodge/channel/letters.
- Regression tests: new `Assets/_Project/Tests/BossFightTests.cs` (+meta) covers catalogue completeness, typed gate for BAT and CALC, event firing and weapon preservation. Offline checks: RulesHarness 235/235, clean `dotnet build Wreckabulary.csproj` 0 errors, project checker 0 errors / trace 21/21; report refreshed.
- Lesson: never use `WordsOverride` as a small allowlist in a mode that still needs normal weapons — MovingDayDirector already merges its checklist into the full catalogue.
